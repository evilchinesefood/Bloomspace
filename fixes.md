## Tasks

### 1. ✅ DONE [CRITICAL] Hoist `killSeedling`'s field list out of the hot path

**Location:** `Sim/World.js:107-133`
**Problem:** `killSeedling` allocated a fresh 17-element string array literal on every call (every death, every black-hole reap — many per tick in a battle) and did string-keyed typed-array access, defeating the JIT fast path.
**Fix applied:** Hoisted the field list to a module-level `const SEED_FIELDS` (allocate once); the per-call loop now iterates the shared array.
**Verification:** `npm test` (compaction/death tests still green); no per-death allocation.

### 2. ✅ DONE [MEDIUM] Cache the black-hole list instead of filtering every tick

**Location:** `Sim/World.js:158-160`
**Problem:** `destroyInBlackHoles` ran `world.asteroids.filter(...)` (fresh array + full scan) every tick though black holes never change after map gen.
**Fix applied:** Lazily memoize the black-hole list on `world._blackholes` (computed once, reused); early-return when empty.
**Verification:** `npm test` (black-hole annihilation test still green).

### 3. ✅ DONE [HIGH] Refund energy when a tree's spawn hits the seedling cap

**Location:** `Sim/Trees.js:103-112`
**Problem:** `spawnSeedling` returns `-1` at the 4096 cap, but the seedling-tree path spent energy and reset the cooldown regardless — silent late-game production stall with energy draining.
**Fix applied:** Spend energy only after a successful spawn; on a `-1` (capacity) result, refund the energy and leave the cooldown short so it retries next interval.
**Verification:** `npm test` + a new Trees test driving a world to capacity (task 8).

### 4. ❌ REVERTED — NOT A BUG [was HIGH] Send-fraction floor sending 0

**Location:** `Sim/Seedlings.js:254`
**Original claim (Code Reviewer):** `floor(1 × 0.5) = 0` — a 1-ship rock at <100% sends nothing; treat as a footgun and floor to `max(1, …)`.
**Why reverted:** The filter pass found an explicit test — `"tiny fraction with few eligible sends 0 (floor)"` in `Sim/Seedlings.test.js:148-156` — asserting `sendSeedlings(..., 0.01, 0) === 0`. The floor-to-zero is **intentional, tested design**: the send-amount slider is meant to be able to dial down to "send nothing." Changing it would break that test and that design. No code change kept; only the code comment was clarified to note the floor is deliberate. See "Ignored".

### 5. ✅ DONE [MEDIUM] Use `OWNER_NEUTRAL` instead of magic `-1` in combat

### 6. ✅ DONE [LOW] Replace `Math.hypot` with `Math.sqrt(dx*dx+dy*dy)` in seedling hot paths

**Location:** `Sim/Seedlings.js:28, 62, 149`
**Problem:** `Math.hypot` is materially slower than the squared-sum sqrt in V8; called per in-flight seedling per tick.
**Fix applied:** Inlined `Math.sqrt(dx*dx+dy*dy)`; the existing `|| 1` / fallback guards still cover the zero case.
**Verification:** `npm test` (transit/sling routing tests green — identical results).

### 7. ✅ DONE [HIGH] Assert the `id === index` invariant for `world.asteroids`

**Location:** new test in `Sim/MapGen.test.js`
**Problem:** Every seedling `home`/`target`/`dest` is an index that doubles as `asteroid.id`. The invariant `asteroids[i].id === i` is load-bearing (Combat, Picking, AsteroidView, Hud all rely on it) but asserted nowhere — a future `sort`/`filter` would corrupt all state silently.
**Fix applied:** Added a test asserting `world.asteroids.every((a, i) => a.id === i)` across several seeds/sizes.
**Verification:** `npm test` shows the new test green.

### 8. ✅ DONE [HIGH] Add a SW SHELL ↔ import-graph sync test

**Location:** new test file `Sim/SwShell.test.js`

### 9. ✅ DONE [MEDIUM] Route `orbitEl` through the change-guarded `setHtml`

### 10. ✅ DONE [CRITICAL] Handle unsolicited WebGL context loss

**Location:** `Render/Scene.js` (renderer), `Game.js:86-108` (render loop)
**Problem:** No `webglcontextlost`/`webglcontextrestored` listeners. A GPU reset (common on mobile under memory pressure) makes `composer.render()` throw every frame with a black canvas and no recovery.
**Suggested fix:** Add `canvas.addEventListener("webglcontextlost", e => { e.preventDefault(); paused=true })` in Scene; guard `composer.render()` in `Game.render`; rebuild renderer/composer/views on `webglcontextrestored`. Minimal version (preventDefault + render guard) is low-risk; full restore is more involved.
**Why deferred:** Touches the render path and can only be truly verified in a browser; left for a session that can drive the live game.
**Verification:** In devtools, trigger context loss (`WEBGL_lose_context`) and confirm the loop doesn't error and recovers.

### 11. [HIGH] Size the composer/bloom by device pixels, not CSS pixels

**Location:** `Render/Scene.js` resize handler
**Problem (per Frontend agent):** `composer.setSize(w, h)` may be receiving CSS px while the renderer scales by pixel ratio, so on HiDPI/mobile the post-processed image renders at 1× and upscales (soft). **Unverified** — needs confirming against the actual resize code and three's EffectComposer behavior before changing; a wrong change regresses image quality.
**Suggested fix:** Pass `composer.setSize(w * pr, h * pr)` (pr = `renderer.getPixelRatio()`); add a DPR-change listener to re-run resize.
**Why deferred:** Uncertain finding + browser-only verification.
**Verification:** Compare rendered sharpness on a 2× display before/after; check `composer` render-target sizes in devtools.

### 12. [MEDIUM] Add touch pan + pinch-zoom

**Location:** `Render/Scene.js:212-213` (pan gated to `button === 1 || 2`)
**Problem:** Touch pointers report `button === 0`, so a landscape mobile PWA (`orientation: landscape`) has no camera pan/zoom at all; combined with `touch-action: none`, mobile users are locked at fit-all and can't reach small bodies.
**Suggested fix:** Track active touch pointers — single-finger drag-to-pan (distinguished from select by threshold/timer) + two-finger pinch-to-zoom.
**Why deferred:** This is a feature addition, not a bug fix; needs device testing.

### 13. [MEDIUM] Dispose per-match GPU resources

**Location:** `Game.js:110-125`, all `Render/*` views
**Problem:** `destroy()` calls `renderer.dispose()` + `forceContextLoss()` but never disposes the geometries/materials/procedural CanvasTextures the views created → JS-heap/canvas growth across many New Game cycles (masked per-cycle by `forceContextLoss`).
**Suggested fix:** Give each view a `dispose()` that frees its own geometries/materials/textures; call them in `Game.destroy` before `renderer.dispose()`. Keep the module-cached shared `_glowTex` in AsteroidView un-disposed (deliberately shared).
**Why deferred:** Medium risk (double-dispose / disposing shared resources) and browser-only verification.

### 14. [MEDIUM] Expose sim death events instead of polling count deltas for FX

**Location:** `Game.js:64-92`, would add a per-tick scratch in `Sim/World.step`
**Problem:** Render infers deaths by comparing `world.seed.count` between frames — misses/merges deaths at high speed or low FPS (acknowledged as "visual sugar only").
**Suggested fix:** Have `step()` accumulate a per-tick `world.events.deaths` (cleared at top of step) that Render drains. Keeps Sim pure + testable.
**Why deferred:** Larger refactor crossing the sim/render seam; cosmetic payoff.

### 15. [MEDIUM] Single source of truth for the build/cache version

**Location:** `Sw.js:3` (`bloomspace-v20`) + `Ui/Menus.js:169` ("build v20")
**Problem:** Two hand-maintained version strings that must agree every deploy; easy to desync → stale-build confusion.
**Suggested fix:** Export one `VERSION` constant the menu imports; the SW (separate context, can't ES-import the app graph) keeps its own constant but add a test asserting the two strings match.
**Why deferred:** Low severity; partly constrained by the SW being a separate module context.

### 16. [LOW] Centralize `MAX_PLAYERS` (resolve the 3 / 6 / 8 cap mismatch)

**Location:** `Combat.js:36` (`MAXO=8`), `Render/Palette.js:7-14` (6 colors), `Ui/Menus.js:226-230` (3-AI cap)
**Problem:** Three modules imply three different max-player counts. A future "4 AI" option would create silent same-body-combat asymmetry, not a crash.
**Suggested fix:** Export one `MAX_PLAYERS` from `World.js` and derive `MAXO`, palette length, and the Menus dropdown from it.

### 17. [LOW] Name the `kind` / `status` magics; rename duplicated `orbitersAt`

**Location:** `kind` literals across `Seedlings.js`/`Trees.js`/`Hud.js`/`SeedlingView.js`; `status` strings; `orbitersAt` in both `Trees.js` (all states) and `Ai.js` (ORBIT only)
**Suggested fix:** `export const KIND = { FIGHTER: 0, DEFENDER: 1 }` and `WORLD_STATUS` from `World.js`; rename the two `orbitersAt` to reflect their differing semantics (e.g. `homedCount` vs `deployableCount`).

### 18. [LOW] `flipOwnership` / `updateRally` O(rocks × seedlings) scans

**Location:** `Combat.js:164-195`, `Seedlings.js:211-231`
**Problem:** Both scan the full SoA per owned/rallied rock each tick. Author-acknowledged; genuinely fine at v1 scale (~26 rocks).
**Suggested fix (only if scale grows):** Query the already-built spatial grid cells within `reach` of each rock instead of scanning all seedlings.

## Ignored (intentional / expected)

- **SW cache-first strategy for first-party files** — The README states "a fresh git clone runs offline"; cache-first is the deliberate offline-first choice. (Keeping the version in sync — task 15 — is still worth doing; switching to network-first is **not**.)
- **Death/flower puffs approximated from render-side polling** — Code comment explicitly marks it "visual sugar only / non-authoritative." Exactness isn't required (the proper event channel is the optional task 14).
- **No tone mapping (`NoToneMapping`)** — A deliberate look choice; bloom threshold is tuned around it. Changing tone mapping is an art decision, not a bug.
- **Buildless / no bundler / manual SW version bump** — Core stated design constraint ("no build step"). The fix is to _guard_ the manual steps with tests (tasks 8, 15), not to add a build.
- **Keyboard-inoperable canvas / minimal a11y** — Acceptable scope for a pointer-driven RTS; the HUD controls themselves are focusable Web Awesome components.
- **`id === index` coupling itself** — Intentional (it's what makes the SoA model cheap). We add an assertion (task 7) rather than replacing it with an id→index map, which would cost the model's simplicity.
- **Send-fraction floors to 0 at low slider values** (task 4) — Intentional and explicitly tested (`Seedlings.test.js:148`). The slider is designed to be able to send nothing; `floor` is the mechanism, not a bug.
